## Major issues closed in this iteration

1. **Network separation:** Arc/EVM import, env, address, deployment, symlink, and hardlink dependencies were severed.
2. **Stellar-native identity:** G-account and C-contract address verification separated; invalid StrKey fail-closed.
3. **Ownership message:** G-account ownership proof migrated to SEP-53 Final prefix + SHA-256 + Ed25519 model and tested with the official vector.
4. **Soroban auth:** owner/admin/validator/reviewer paths use `Address.require_auth()`; the full auth tree is also verified for at least one transaction.
5. **AgentRegistry:** owner-bound registration, fixed validator, report hash/URI/score, allowlist reviewer, single review, checked sum, URI limit, TTL, and typed events added.
6. **Report integrity:** zero agent/metadata/request/report hashes are rejected; backend carries the canonical JSON hash to the chain call.
7. **On-chain finality:** `confirmed=true` is only possible with the expected contract event + request/report hash + `getTransaction=SUCCESS`.
8. **Event ingest:** SQLite idempotency with cursor and unique event ID; only permitted contract/event and successful contract call scope are accepted.
9. **Escrow:** SAC client, role separation, fee/fee recipient snapshot, deadline, late delivery rejection, completion/refund/dispute, and atomic transfer boundaries added.
10. **Data correctness:** Horizon sequence is not counted as transaction count; not presented as an RPC history service.
11. **SEP boundary:** Active/Final/Draft separation and separation of SEP-24/31/38 payment roles from agent validation are documented.
12. **API/privacy:** write auth/rate limit, LLM privacy opt-in, and private `source_ref` mask added.
13. **Test security:** offline test script disables signer/contract/RPC/LLM/IPFS/provider writes and uses a temporary data directory.
14. **Full quorum:** Seven unique auditor identities and seven expected dimensions must match exactly to generate a report; timeout or missing dimension is not silently accepted.
15. **Stellar policy guard:** Each auditor must carry the same versioned Stellar policy identity; incorrect identity/dimension, timeout, error, and duplicate finding close the audit fail-closed.
16. **Evidence calibration:** `CONFIRMED` finding without evidence text is downgraded to `INFERRED`; failed scenario penalty scales according to evidence grade.
17. **Report v2 provenance:** Policy version, audit-input commitment, finding-set commitment, coverage, external handlers, and determinism fields added to JSON/Markdown report.
18. **Stellar assurance:** `verified|partial|simulated` reported separately; `SAFE` is not granted if the real indexer/RPC tie with ownership is missing. Horizon account registration does not count as behavioral evidence.
19. **LLM boundary:** Artifact prompt is passed within untrusted-data delimiter; private audit does not go to the auditor or synthesis LLM without explicit opt-in; egress is logged separately.
20. **Continuous audit:** Finding-set changes other than score, newly verified high/critical findings, badge, and assurance regressions generate alerts.
21. **Stake accuracy:** Different expertise dimensions are not slashed by distance to the overall score; until external ground truth/adjudication arrives, ELO is neutral and payouts are equal.
22. **Testnet release:** Registry and escrow pinned WASM hashes match the chain readback; deploy/init/role transactions are `SUCCESS`.
23. **Live agent validation:** `register → request → respond → review` completed with separate validator/reviewer accounts and four typed events committed to the persistent store.
24. **Funded escrow:** Real 1 XLM `create → fund → submit → complete` on native XLM SAC; 0.15 XLM fee + 0.85 XLM payout and zero escrow balance verified.
25. **Runtime deployment evidence:** Configured C-ID alone is not sufficient; manifest ID/hash match and live deploy tx `SUCCESS` are required together.

## Open findings and actionable fixes

### STL-H01 — Single admin root of trust

**Severity:** High · Governance/operations  
Registry validator/reviewer and escrow fee management depend on a single admin address. Compromise or operational error could affect the entire trust state.

**Fix:** Make the admin a threshold/multisig or a limited governance contract address instead of a direct hot G-account. The rotation function must carry two-stage state:

```rust
pub fn propose_admin(env: Env, admin: Address, next: Address, activate_at: u64) {
    admin.require_auth();
    // next != admin, activate_at >= ledger timestamp + delay
    env.storage().instance().set(&DataKey::PendingAdmin, &(next, activate_at));
}
```

Add separate auth/event for acceptance and cancel; continuously monitor validator/reviewer update events.

### STL-H02 — Testnet external-signer lifecycle closed

**Status:** Closed for Testnet · Release evidence  
Pinned WASM was deployed with an external Stellar CLI signer without carrying a backend signer. Request/response/review and funded escrow transaction hash, ledger, typed event, state, and WASM readback evidence were linked to the [release manifest](../deployments/stellar-testnet.json). This closure is not a claim for mainnet, hardware signer, or production key management.

### STL-H03 — Missing property/fuzz and real C-account negative tests

**Severity:** High · Testing/correctness  
Unit tests prove selected paths; they do not prove all state combinations and the custom account `__check_auth` behavior.

**Fix:** Run the following invariants in property tests:

```text
review_total == sum(unique reviewer scores)
completed escrow token delta == amount
fee + provider payout == funded amount
request validator never changes
responded request cannot respond again
submit/complete fails after deadline
```

Run missing/incorrect auth context, replay, and threshold scenarios with a separate minimal C-account test contract.

### STL-M01 — Missing SEP-45 auth server

**Severity:** Medium · Authentication/interoperability  
C-account web session claim cannot be established without a full SEP-45 challenge and validation server; SEP is Draft.

**Fix:** Keep the feature closed. If implemented, pin the specific SEP commit, add nonce/domain/network binding and replay store; manage G/M session as SEP-10 and C session as SEP-45 with separate endpoints and test suites.

### STL-M02 — Missing event retention and operational proof

**Severity:** Medium · Data operations  
SQLite dedup/cursor exists; the gap outside of provider retention, cursor loss, and ingest lag behavior were not proven live.

**Fix:** Add `last_success_ledger`, `last_event_ledger`, `cursor`, provider watermark, and gap list to the worker state. Generate two redundant cursor snapshots, lag SLO, and an alert when approaching the retention limit.

### STL-M03 — Missing public discovery/independent reproducibility

**Severity:** Medium · Release/documentation  
Local/chain WASM hash match with Contract ID exists; but there is no published `stellar.toml` and independent rebuild record from a second clean environment.

**Fix:** Publish only verified endpoints and contract IDs in SEP-1 post-deployment. Produce WASM in two clean environments and write the SHA-256 match and toolchain digests to the release manifest; follow SEP-55/58 Draft scope within the claim boundary.

### STL-M04 — No auditor calibration ground truth

**Severity:** Medium · Audit quality  
Intent, security, and Stellar-native scores do not measure the same target; proximity to the overall score is not auditor accuracy. Therefore, the previous consensus-distance slash/ELO mechanism was disabled. The current leaderboard shows the number of audits, it does not prove prediction accuracy.

**Fix:** Create a versioned, expert-labeled benchmark corpus for Stellar agent/Soroban/SEP cases. Finding-level blind adjudication, false-positive/false-negative, severity calibration, and evidence sufficiency results should be the ELO/slash input after the appeal window.

### STL-L01 — No SBOM/advisory archive

**Severity:** Low · Supply chain  
Pinned SDK, `cargo clippy`, and `pip check` pass; these are not a CVE scan.

**Fix:** Add `cargo audit`, `pip-audit`, CycloneDX SBOM, and independent WASM hash results to the immutable release bundle. If there is an advisory exception, record it with owner, duration, and rationale.
